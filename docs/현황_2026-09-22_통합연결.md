# 통합 현황 (2026-09-22 기록, 2026-09-23 갱신)

이 문서는 현재 구현과 검증 경계를 빠르게 인계하기 위한 요약이다. 실행은 [한 PC 통합 실행](한_PC_통합_실행_가이드.md), 상세 계약은 [API](API_명세서_프론트-백엔드.md)·[Socket](Socket_명세서_백엔드-하드웨어.md)을 따른다.

| 연결 | 현재 상태 |
| --- | --- |
| 프론트 → 백엔드 | HTTP로 아이·위험·리포트 조회와 전원·안전 처리 요청 |
| 백엔드 ↔ 로봇 PC | WebSocket 명령/상태/결과, HTTP 탐지 이미지 수신 |
| 백엔드 ↔ PostgreSQL | Flyway 스키마·아이/위험/원본/상태/명령 저장 |
| 로봇 PC ↔ Pi | 카메라 영상·모터 명령. Pi 서버는 별도 실행 |

## 핵심 동작

| 상황 | 구현된 처리 |
| --- | --- |
| 프로필 선택 | 데모 프로필 3명이 한 기기를 공유. 마지막에 연 프로필이 다음 탐지의 연결 대상 |
| 전원 | 프론트가 최신 상태를 보고 ON/OFF 명령. OFF에도 통신은 유지 |
| 삼킴 위험 | 로봇 정지 후 보호자가 직접 제거 재확인 또는 수동 이송을 선택. 사용자 선택 전 자동 재개 없음 |
| 수동 이송 | 단일 물체를 팔에 확보한 뒤 마커 기준 이동. 후진 후 물체가 마커 주변에 연속 감지돼야 성공 |
| 생활공간 위험 | 알림만 표시. 사용자가 확인 완료하면 DB에 시각 저장·`RESOLVED` 처리하고 알림·활성 지도에서 제거. 같은 라벨의 연속 감지는 완료 상태 유지 |
| 동시 감지 | 삼킴 위험 우선. 원본은 물체별 이벤트, 같은 이름의 활성 위험은 한 건으로 병합 |
| 처리 완료 | 백엔드가 기기 결과 증거를 확인한 뒤에만 위험을 `RESOLVED`로 변경 |

삼킴 위험도는 영아기 `HIGH`, 걸음마 `VERY_HIGH`, 유아 활동기 `MEDIUM`이다. 생활공간 위험은 각각 `HIGH`, `HIGH`, `VERY_HIGH`다. V13은 기존 활성·해결 삼킴 위험의 등급도 현재 아이 단계로 다시 계산한다. **서버가 꺼져 있으면 DB 마이그레이션은 아직 적용되지 않는다.**

## 검증·남은 사항

| 구분 | 상태 |
| --- | --- |
| 코드 검사 | 백엔드 단위 테스트, 프론트 빌드·린트·테스트, 하드웨어 단위 테스트 통과 |
| 실물 연결 | 이전에 직접 제거 첫 시도를 확인했으나 최근 다중 위험·재개·이송 변경 이후 전 구간 실물 재시험 필요 |
| 자동 이송 | 목업. 사용자 명시 요청에 의한 안전 이송만 연결 |
| 지도 위치 | 실제 좌표 미수신. 화면 마커는 예시이며 선택한 위험 한 건만 표시 |
| 같은 라벨 여러 물체 | 위험 건이 병합되고 이송은 대상을 구분할 수 없어 거부. 개별 처리를 원하면 추적 ID 계약 필요 |
| 주사위·이송 장치 | 주사위 모델 가중치, 반원형 팔 확보 시간, 마커 가림, 후진 뒤 배치 재확인, 후진/회전 시간 실물 검증 필요 |
| 보안·운영 | 보호자 인증·소유권 검증·TLS 없음. 개발망 전용, 백엔드 한 인스턴스·로봇 제어 런타임 한 개만 실행 |
| 데이터 보존 | 사진 원본·로컬 업로드 대기열의 보관 기간/정리 정책 미정 |

과거 네트워크 장애와 수동 복구 기록은 Git 이력의 2026-09-22 버전을 참고한다. 이 문서는 과거 검증 결과를 현재 변경의 실물 검증 완료로 간주하지 않는다.
