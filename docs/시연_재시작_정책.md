# 시연 재시작과 위험 확인 (2026-09-23)

- 백엔드 시작 시 `deni.demo.reset-on-startup` 기본값은 `true`다. 기존 `ACTIVE` 위험을 모두 `RESOLVED`로 전환한다. 이미지·탐지 이력·아이 프로필·기기 등록은 삭제하지 않는다. 이송 성공은 `TEMPORARY_COMPLETED`이며 물체를 안전 구역으로 옮겼을 뿐이라 위험 자체는 `ACTIVE`로 남는다. 따라서 다음 백엔드 시작 때 완료 처리된다. 직접 제거 성공만 그 자리에서 `RESOLVED`가 된다.
- 이전 명령 중 `QUEUED/SENT/DELIVERED/UNKNOWN`은 `EXPIRED`, 오류 코드는 `DEMO_SESSION_RESTARTED`로 끝낸다. 실행 성공으로 기록하지 않는다. 완료된 명령과 불변 접수 기록은 유지한다. 늦게 도착한 이전 명령 결과는 다시 적용하지 않는다.
- DB 초기화 후, HTTP/기기 명령 스케줄러 시작 전에 한 트랜잭션으로 처리한다. 실패하면 시작을 중단한다. 스키마 변경은 없다. 재시작 자동 처리를 끄려면 `DEMO_RESET_ON_STARTUP=false`를 지정한다. 공용 DB의 모든 기존 활성 위험에 적용되므로 백엔드는 한 인스턴스만 실행한다.
- 여기서 재시작은 **Spring Boot 백엔드 프로세스 재시작**이다. 화면 새로고침·Pi 카메라·하드웨어 런타임 재시작·프론트 전원 토글은 이 처리를 수행하지 않는다. 새로운 탐지는 새 활성 위험을 생성할 수 있다. 자동 처리는 사용자 확인이 아니므로 `acknowledged_at`을 새로 기록하지 않는다.
- 생활공간 위험과 삼킴 위험은 같은 케어 맵 화면에서 선택한다. 생활공간 위험을 선택하면 케어 맵을 그대로 두고 해당 감지 사진과 확인 완료 버튼을 함께 표시한다. 삼킴 위험이 남아 있어도 생활공간 위험만 개별 완료할 수 있다. 삼킴 위험의 이송·직접 제거 확인 흐름은 유지한다.
- Pi 통합 서버가 모든 카메라 프레임을 송출 전에 항상 180도 회전한다. PC는 받은 JPEG를 다시 돌리지 않고 화면·물체 탐지·ArUco·업로드에 그대로 쓴다. 회전 선택 옵션은 없으며 실제 마커 좌우와 영상 좌우·bearing·조향을 함께 확인해야 한다.

실물 검증은 미실시다. IT-05(전체 이송), IT-08(동일 라벨 다중 물체), IT-12(마커 미검출·배치 검증 실패)를 다시 수행해야 한다. 함께 감지된 생활공간 위험을 선택해 사진 표시 → 확인 완료 → 그 건만 제거 → 남은 삼킴 위험 선택도 확인한다.
