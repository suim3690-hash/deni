# 핵심 MVP 서비스 흐름도

각 `.mmd` 파일은 코드 블록 없이 저장한 Mermaid `flowchart` 원본이다. Mermaid 지원 편집기·뷰어에서 열거나 코드를 붙여 넣어 렌더링할 수 있다.

## 기준과 범위

- [기능 요구사항](../기능요구사항명세서.md)의 기존 7개 핵심 유스케이스와 [최신 유스케이스 명세서](../유스케이스명세서.md)의 TKS_008을 반영했다. 추가 첨부 기준으로 위험 판단 후 즉시 정지와 월간 성장 리포트까지 반영했다.
- 기능별로 사용자·시스템·외부 기기 영역을 구분한다. 사용자 참여가 없는 감지 흐름에는 사용자 행동을 임의로 추가하지 않는다.
- 파란 영역은 보호자, 녹색 영역은 서비스 내부, 주황색 영역은 외부 기기 드니다. 색과 함께 영역 이름으로 역할을 표시한다.
- 푸시 공급자, 외부 지도·이미지 API는 미정이다. 존재를 가정한 외부 시스템 노드를 추가하지 않는다. 발송 처리와 단말 수신은 구분하고 수신 확인을 발송 성공 조건으로 사용하지 않는다.
- 주요 정상·대안 흐름과 잘못된 완료 표시를 방지하는 핵심 실패 분기만 포함한다. 상세 입력, 내부 API 호출, 모든 오류별 재시도는 생략한다. 공통 권한·중복·저장 정책은 기능 명세를 따른다.
- 실패 분기는 기능 명세의 대안·예외를 시각화한 것이다. 세 지원 연령 구간은 후속 사용자 결정에 따르며 위험·알림·이동 기준 등 미정 정책의 수치를 새로 정의하지 않는다.
- 파일 간 연결은 ‘TKS_…로 전달’ 또는 ‘…에서 전달’이라는 노드로 표현한다. 연결 상태 확인은 감지 중 계속 유효해야 하며, 홈 조회 1회가 이후 연결을 보장하지 않는다.

안전 처리에서는 직접 제거 완료 버튼 뒤 기기의 위험물 재확인과 실제 운행 재개를 분리했다. 위험물이 남아 있거나 재확인에 실패하면 정지를 유지한다. 이동 결과가 불명확하면 직접 제거를 즉시 실행하도록 연결하지 않고 확인 필요 상태로 남긴다. 리포트는 월 선택·성장단계 변화·감지 통계·TKS_007의 실제 안전 처리 내역·다음 단계 예고를 포함한다. 단계 자동 전환과 변경 이력도 프로필 흐름에 반영했다.
