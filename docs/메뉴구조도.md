# LG 드니 앱 메뉴구조도

> v0.1 | 2026-09-16 | UX 정보구조 설계안

## 1. 설계 기준

[PRD·MVP](PRD_MVP_ThinQ_Kids_SafeGuard.md), [기능 요구사항](기능요구사항명세서.md), [유스케이스 명세서](유스케이스명세서.md)의 최신 범위를 기준으로 작성했다. TKS_008은 성장단계 변화·감지 통계·안전조치 변경사항·다음 단계 예고를 포함하는 **월간 성장 리포트**다.

기존에 메뉴 원본과 SCR 번호가 없었으므로 **메뉴 계층, 화면 분리, SCR ID와 MVP 색상 분류는 이번에 작성한 설계안**이다. 기존 요구사항의 확정된 화면 ID로 소급 해석하지 않는다. 첨부의 예시 `SC-04`는 본 문서의 SCR 체계와 별도이며 자동 대응하지 않는다.

- 표현 순서: **LG 드니 → 1Depth → 2Depth → 3Depth → 화면**.
- Depth는 논리적인 정보 분류다. 사용자가 반드시 네 번 메뉴를 눌러 진입한다는 뜻이 아니며, 하단 탭 구성도 확정하지 않는다.
- 1Depth는 홈·아이·안전 케어·리포트·확장 서비스로 구분한다. ‘확장 서비스’는 후속 범위를 정리하기 위한 논리 영역이며 MVP에는 노출하지 않는다.
- 화면 내부 버튼·입력 항목·통계 카드·달력 선택창·오류 안내는 별도 메뉴나 화면으로 만들지 않는다.
- 안전 처리 방법과 처리 결과는 각 화면 안에서 상태별로 제공한다. 직접 제거·안전 위치 이동을 별도 메뉴로 나누지 않는다.
- 감지 수신·위험 판단·정지 명령·푸시 발송·자동 단계 전환·데이터 삭제는 백그라운드 처리다. 별도 메뉴 없이 관련 화면과 연결한다.

## 2. MVP 범위 분류

| 분류 | 색상 | 의미 |
| --- | --- | --- |
| MVP 핵심 | 보라색 | 위험 확인·안전 처리·월간 성장 리포트를 제공하는 화면 |
| MVP 필수 기반 | 노란색 | 홈 진입·기기 상태 확인·아이 등록·Safety Profile 확인을 지원하는 화면 |
| MVP 이후 | 회색 | PDF에 제시된 확장 경험을 화면 후보로 정리한 영역. 구현 범위·FR은 미확정 |

이 분류는 FR의 상·중·하 우선순위와 다르다. **월간 성장 리포트는 우선순위 ‘중’이지만 최신 MVP에 포함되므로 보라색**으로 분류한다.

## 4. 화면 분리와 진입 원칙

- 홈에서 위험 위치·상세와 월간 리포트로 진입할 수 있다. 다이어그램은 메뉴 계층만 표시하므로 이러한 바로가기 선은 그리지 않는다.
- ‘실시간 위험 감지 & 맵’과 ‘위험 상세’는 논리 화면을 구분한 것이다. 실제 UI에서 한 화면의 상세 패널로 통합할 수 있으며 결정 시 SCR 매핑을 갱신한다.
- 아이 등록, 프로필 적용 결과, 안전 처리 결과는 항상 노출되는 최상위 메뉴가 아니라 해당 흐름 중 제공되는 화면이다.
- 월 선택은 리포트 내부 기능이다. 성장단계 변화·통계·변경사항·다음 단계 예고도 리포트 내부 영역으로 유지한다.
- 가입·로그인·기기 등록·환경설정은 구체적인 화면 요구가 확정되지 않아 독립 메뉴를 추가하지 않는다. 현재 명세의 계정·등록 기기 전제와 접근 권한 검증은 유지한다.
- 외부 푸시 알림은 앱 메뉴 화면이 아니므로 SCR을 부여하지 않는다.

## 5. 집계 및 관리

- 전체: **12개 화면** — MVP 핵심 5개, MVP 필수 기반 3개, MVP 이후 4개.
- MVP 전용: **8개 화면** — 보라색·노란색만 포함. 회색 화면과 자식이 없는 확장 메뉴는 제외한다.
- TKS_004~005는 주로 기기·백그라운드 처리이므로 별도 화면을 만들지 않았다. 화면 수와 유스케이스 수는 1:1 관계가 아니다.
- 추가 확정 항목: 실제 내비게이션 배치, 맵·상세의 통합 여부, 후속 화면의 FR, 안전조치 변경사항의 데이터 의미.
