# 프론트–백엔드–하드웨어 통합 테스트

안전한 공간에서 모터를 감독할 담당자와 비상 정지 수단을 준비한다. **백엔드 한 인스턴스, `care_runtime.py` 한 인스턴스**만 실행하고 같은 기기 ID의 시뮬레이터를 끈다. 실행·인증 준비는 [한 PC 통합 실행](한_PC_통합_실행_가이드.md)을 따른다.

## 1. 로컬 검사

| 영역 | 명령 | 확인 |
| --- | --- | --- |
| 백엔드 | `cd backend; .\gradlew.bat test` | 단위 테스트. 공유 DB 테스트는 `RUN_DB_TESTS=true`일 때만 포함 |
| 프론트 | `cd frontend; npm run build; npm run lint; node --test tests/*.test.mjs` | 빌드·정적 검사·화면 로직 |
| 하드웨어 | `cd hardware; .\.venv\Scripts\python.exe -m unittest discover -s tests -q` | 제어·탐지 로직 |
| 로봇 없이 흐름 | `cd hardware; .\.venv\Scripts\python.exe check_without_frontend.py` | 명령·위험 처리 모의 검사 |

공유 DB 테스트와 Flyway V12·V13 검증은 DB 접속 가능한 환경에서 별도로 실행한다. 실제 로봇 시험을 대신하지 않는다.

## 2. 연결·동작 시나리오

| ID | 실행 | 기대 결과 |
| --- | --- | --- |
| IT-01 | 백엔드 → 로봇 PC 런타임 연결 | `robot-state` ONLINE·`stale=false`, 최근 상태 갱신 |
| IT-02 | 프론트 전원 ON/OFF | 명령 ID별 실제 결과 확인, OFF 시 모터·탐지 정지와 통신 유지 |
| IT-03 | 삼킴 위험 한 건 감지 | 원본 이벤트·이미지·위험 건 저장, 로봇 `HAZARD_PAUSED`, 사용자 선택 전 정지 유지 |
| IT-04 | 사용자 직접 제거 후 완료 클릭 | 새 영상에서 해당 라벨 2초 연속 미검출 시에만 `RESOLVED`; 남으면 정지·알림 유지 |
| IT-05 | 수동 안전 이송 | 단일 대상 정렬·확보 후 물체가 화면에서 사라져도 마커를 따라 진행. 도착·후진 뒤 물체가 마커 주변에 1초 연속 보여야 완료 보고·`RESOLVED` |
| IT-06 | 생활공간 위험 확인 완료 | 삼킴 위험 우선 처리, 확인 시 `acknowledgedAt` 저장·`RESOLVED` 전환, 알림과 지도 마커 제거 |
| IT-07 | 서로 다른 삼킴 물체 2건 | 한 건 처리 뒤 남은 건은 미해결·정지 유지, 별도 재개 거부 |
| IT-08 | 같은 라벨 2개 | 위험 건 병합·사진 갱신 확인. 직접 제거는 모두 사라져야 성공, 이송은 다중 대상 거부 |
| IT-09 | 동일 프레임 삼킴+생활 위험 | 원본 이벤트 각각 저장·프레임 사진 연결, 홈 알림 한 개+건수, 삼킴 우선 |
| IT-10 | 중복 요청·재접속·결과 누락 | 같은 키/이벤트 재실행 없음. `UNKNOWN`을 성공으로 표시하지 않음 |
| IT-11 | 기존 DB 위험 기록 | 백엔드 시작 후 Flyway V13 적용, 활성·해결 삼킴 위험이 현재 아이 단계로 변경 |
| IT-12 | 이송 실패 안전성 | 마커 미검출 시 전진 금지·우회전 탐색 후 실패, 배치 재확인 실패 시 정지·위험 `ACTIVE` 유지 |

## 3. 완료 기록

| 기록 | 내용 |
| --- | --- |
| 환경 | Git 커밋, 기기 ID, 모델 가중치 해시, 백엔드/PC/Pi 실행 위치 |
| 사건 | `eventId`, `hazardId`, `commandId`, 요청·결과 시각 |
| 증거 | 프론트 화면, 백엔드/로봇 로그, 읽기 전용 DB 조회 |
| 판정 | 통과·실패·미실행과 재현 순서, 담당자 |

현재 로컬 자동 검사는 통과했으나, 최근 다중 위험·위험도·재개·이송 변경 이후 **IT-01~12 전체 실물 검증 완료로 표시하지 않는다**. 시험 결과를 채운 뒤 팀이 안전 처리와 실패 경로를 함께 확인한다.
