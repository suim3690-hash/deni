# 프론트–백엔드–하드웨어 통합 테스트

세 영역이 같은 기능의 완료 조건을 공유하기 위한 시나리오다. 하드웨어 지원 기능이 확정되면 지원되는
항목부터 실행하며, 미지원 기능은 프론트 비활성화·준비 중 표시가 정상 결과다.

## 1. 사전 조건

- 프론트·백엔드·하드웨어가 같은 `deviceId`를 사용한다.
- 백엔드에서 아이와 기기 등록을 완료한다.
- 세 PC의 시계를 동기화한다.
- 백엔드 주소와 포트에 프론트·하드웨어 PC가 접근할 수 있다.
- DB·기기 키는 환경변수로 설정한다.
- 각 실행 로그에 `commandId`·`eventId`를 남길 수 있다.

## 2. 우선 통합 시나리오

| ID | 시나리오 | 실행 | 기대 결과 |
| --- | --- | --- | --- |
| IT-01 | 상태 보고 | 하드웨어가 `ROBOT_STATE` 전송 | 백엔드 저장 후 홈에 동작·이동 상태 표시 |
| IT-02 | 일시정지 성공 | 프론트 일시정지 → 백엔드 → 하드웨어 | ACK 뒤 실제 `PAUSED` 결과가 저장되고 화면 갱신 |
| IT-03 | 중복 요청 방지 | 같은 키·명령 ID로 재전송 | 로봇 동작은 한 번만 실행하고 같은 결과 반환 |
| IT-04 | 연결 단절 | Socket 종료 후 프론트가 명령 요청 | 성공 표시 없이 연결 오류·미확정 안내 |
| IT-05 | 명령 만료 | 만료된 명령을 재연결 후 수신 | 하드웨어가 실행하지 않고 `EXPIRED` 반환 |
| IT-06 | 탐지 저장 | 모델이 한 이벤트와 이미지를 전송 | 이벤트 한 건 저장, 목록과 이미지 조회 가능 |
| IT-07 | 탐지 재전송 | 같은 이벤트 ID·내용을 다시 전송 | 중복 행이 생기지 않음 |
| IT-08 | 오래된 상태 | 과거 측정 상태를 최신 상태 뒤에 전송 | 최신 상태를 덮어쓰지 않음 |

## 3. 안전 처리 시나리오

| ID | 선행 조건 | 시나리오 | 기대 결과 |
| --- | --- | --- | --- |
| IT-09 | 재검사 지원 | 직접 제거 후 재확인 | 부재 확인 때만 위험 처리 완료 가능 |
| IT-10 | 재검사 지원 | 위험물이 계속 존재 | `REMAINS`, 로봇 정지 유지, 재개 거부 |
| IT-11 | 재개 지원 | 모든 위험 처리 후 재개 | 실제 `RUNNING` 결과 뒤 화면에 운행 표시 |
| IT-12 | 이송 지원 | 안전 위치 이송 | 실제 완료 결과 전에는 완료 표시 금지 |
| IT-13 | 이송 지원 | 배터리 부족·이동 불가 | 실패 코드와 직접 제거 안내 표시 |

## 4. 시나리오별 기록

각 테스트에서 다음 내용을 남긴다.

| 항목 | 기록값 |
| --- | --- |
| 실행 버전 | 프론트·백엔드·하드웨어 커밋 ID |
| 식별자 | `deviceId`, `commandId` 또는 `eventId` |
| 시간 | 요청·전달·수신·완료 시각 |
| 결과 | 통과·실패·미지원 |
| 증거 | 관련 로그, API 응답, DB 행, 화면 |
| 문제 | 재현 순서와 담당 영역 |

## 5. v2 완료 기준

- 하드웨어 지원 기능표에 `확인 필요`가 남지 않는다.
- 지원 명령은 요청·ACK·최종 결과를 명령 ID 하나로 추적할 수 있다.
- 프론트는 최종 결과 전 성공을 표시하지 않는다.
- 연결 단절·중복·만료 상황에서 위험한 명령을 다시 실행하지 않는다.
- 미지원 기능은 API와 화면에서 동일하게 차단하거나 숨긴다.
- 구현된 시나리오가 모두 통과하고 결과를 팀이 확인한다.
