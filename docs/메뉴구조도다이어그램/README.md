# LG 드니 메뉴구조도 다이어그램

## 원본과 작성 범위

원본은 [메뉴구조도.md](../메뉴구조도.md)다. 기존 문서에 메뉴 계층·SCR ID가 없어 현재 PRD·MVP와 8개 유스케이스를 바탕으로 작성한 **UX 정보구조 설계안**이다. 후속 화면은 기획서의 확장 경험에 근거한 후보이며 확정된 구현 기능이 아니다.

원본 표의 메뉴·화면·ID·분류만 읽어 `.mmd`를 생성했다. 그림 단계에서 새로운 메뉴를 추가하지 않았다.

`.mmd`에는 Markdown 코드 블록 없이 Mermaid 원문을 저장했다. PNG는 그림 도구로 재작성한 이미지가 아니라 해당 `.mmd`의 렌더링 결과다. 전체 그림은 가로 폭이 넓으므로 원본 배율로 확대하면 화면별 ID를 읽기 쉽다.

## 색상 범례

| 분류 | 색상 | 화면 수 |
| --- | --- | --- |
| MVP 핵심 | 보라색 `#EDE4FF` / 테두리 `#8854D0` | 5 |
| MVP 필수 기반 | 노란색 `#FFF3BD` / 테두리 `#C69B21` | 3 |
| MVP 이후 | 회색 `#E8EBEF` / 테두리 `#A5ADB9` | 4 |

색상은 화면 노드에 적용했다. 메뉴 분류 노드는 흰색, 최상위 LG 드니는 남색이다. FR의 상·중 우선순위와 MVP 분류는 다르며 월간 성장 리포트도 MVP 핵심에 포함한다.

## 구조 읽는 방법

- 위에서 아래로 **LG 드니 → 1Depth → 2Depth → 3Depth → 화면** 순서다.
- 화면 노드에는 화면명, SCR ID, 그 아래 FR ID를 표시한다. FR은 새 메뉴 노드가 아니라 화면의 하단 설명이다.
- 후속 화면의 FR은 아직 정해지지 않아 `FR 미정`으로 표시했다.
- 한 화면은 한 부모 경로에 연결한다. 화면 간 바로가기·뒤로가기 선을 넣지 않아 계층선 교차를 피했다.
- 버튼·입력·팝업·내부 통계 항목은 메뉴로 만들지 않았다. Depth는 논리 계층이지 실제 클릭 횟수가 아니다.

## 실제 렌더링 검증

2026-09-16에 Mermaid **12.0.0**의 `parse` 및 `render`를 실행한 뒤, 로컬 headless Chrome에서 렌더링 결과를 PNG로 저장했다. 소스 파일을 직접 읽었으며 외부 이미지 생성 서비스는 사용하지 않았다.

| 검증 항목 | 결과 |
| --- | --- |
| 전체·MVP Mermaid 파싱 및 렌더링 | 두 파일 모두 성공 |
| 원본 표와 화면 ID 대조 | 전체 SCR-001~012, MVP SCR-001~008 일치 |
| 계층 구조 | 모든 화면이 루트→1Depth→2Depth→3Depth→화면 경로를 가짐 |
| MVP 필터 | 회색 화면 4개와 빈 확장 메뉴 제외 |
| PNG 시각 확인 | 한글·SCR·FR 표시, 화면명 줄바꿈, 색상, 연결선 교차·잘림 여부 확인 |

재생성 스크립트는 작업 폴더의 `tmp/build_menu_diagrams.py`, 렌더링 스크립트는 `tmp/menu-render/render.mjs`다. 메뉴 원본 수정 시 두 단계를 순서대로 실행해야 MMD·PNG가 일치한다. 이 스크립트의 브라우저·패키지 경로는 현재 작업 환경 기준이다.
