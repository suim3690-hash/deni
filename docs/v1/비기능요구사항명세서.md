# ThinQ Kids SafeGuard 비기능 요구사항 명세서

> v0.2 | 2026-09-16 | 사용자 첨부 목표 우선 · 나머지 품질 보완은 검토안

## 1. 적용 원칙

근거: [PRD·MVP](PRD_MVP_ThinQ_Kids_SafeGuard.md), [유스케이스 명세서](유스케이스명세서.md), [다이어그램](유스케이스다이어그램.md), [기능 요구사항 명세서](기능요구사항명세서.md).

**사용자 추가 첨부의 3초 판단·정지, 5초 알림 발송, 2초 화면 로딩, 자동 단계 전환, 월 99.5% 가용성을 우선 반영한다.** 해당 수치는 이전 작성자의 제안이 아니라 사용자 제공 목표다. 나머지 부하·표본·복구·보안·접근성 수치 등은 기존 검토안으로 구분한다. 사용자 목표를 p95로 완화하지 않는다. 시험 조건과 측정 완료점은 필요한 범위만 별도 확정한다.

| 첨부 ID | 내부 관리 ID | 사용자 제공 기준 | 적용 시점 |
| --- | --- | --- | --- |
| NFR-DE-001 | NFR-003 | 물체 인식 후 판단·정지 3초 이내 | 알파테스트 |
| NFR-DV-001 | NFR-004 | 위험 판단 후 푸시 발송 5초 이내 | 알파테스트 |
| NFR-DV-002 | NFR-001 | 홈→위험 상세 화면 로딩 2초 이내 | 알파테스트 |
| NFR-TS-001 | NFR-019 | 월령 경계에서 성장단계 자동 전환 정확성 | 클로즈 베타테스트 |
| NFR-AN-001 | NFR-016 | 위험 감지·알림 월 가동률 99.5% 이상 | 알파테스트부터 측정 |
| 취소선 NFR-TS-002 | 활성 요구사항 아님 | 오프라인 중 감지 데이터 무손실 동기화 | 적용하지 않음 |

현재 NFR-015의 저장 상태 재조회는 취소된 오프라인 데이터 무손실 동기화와 다르다. 법령·특정 인증 전체 준수를 선언하지 않는다.

## 2. 측정 조건과 판정 방법

| 구분 | 측정 조건 제안 |
| --- | --- |
| 시험 환경 | 출시 후보와 동일한 빌드·설정으로 시험한다. 서버 자원, DB 규모, 단말·OS, 앱 또는 브라우저 버전, 네트워크 조건을 결과에 기록한다. |
| 기본 부하 | 보호자 세션 20개 동시 사용 + 감지 이벤트 초당 5건, 준비 5분 후 본 측정 30분. 실제 동시 기기 수 목표가 확인되면 조정한다. |
| 화면 성능 환경 | 지연 왕복 100ms 이하, 다운로드 10Mbps 이상 조건의 지정 시험 단말. 정상 연결과 오류 주입 시험을 분리한다. |
| 표본 | 조회·저장 API는 유형별 최소 1,000건, 화면 갱신은 화면별 최소 100회. 이벤트 지연은 최소 1,000건. 정상 요청 실패율도 별도 보고한다. |
| 지연 산정 | 요청·이벤트별 시작/종료 시각의 차이로 산출한다. p95는 표본의 95%가 해당 시간 이하임을 뜻한다. 동시 부하 조건과 표본 수를 함께 명시한다. |
| 실패율 | 유효하고 권한 있는 요청 중 서버 오류·시간 초과 건수 / 해당 요청 전체 수. 의도적으로 잘못된 입력·권한 요청은 성능 분모에서 제외하고 보안·예외 시험으로 평가한다. |
| 100%·0건 기준 | 정의된 시험 집합에서의 기준이다. 모든 실제 환경에서 무결함을 입증한다는 의미가 아니다. 테스트 사례와 반복 수를 남긴다. |
| 판정 | 통과 / 실패 / 미검증 / 정책 미확정으로 구분한다. 외부 연동이 없는 조건부 항목은 적용 없음과 근거를 기록한다. 모의 시험을 실기기 검증으로 대체하지 않는다. |

## 3. 성능

| 비기능 ID | 구분 | 요구사항 | 측정 기준 |
| --- | --- | --- | --- |
| NFR-001 | 성능 | 홈에서 위험 감지 상세 화면으로 전환 시 2초 이내 로딩을 완료해야 한다. | 첨부 NFR-DV-002 / 알파테스트. 사용자 전환 요청 시각→위험 상세의 합의된 필수 정보 표시 완료 시각 ≤ 2초. 구간별 p95의 합으로 대체하지 않는다. 지도·이미지를 완료에 포함하는 범위와 시험 환경은 확정 필요. |
| NFR-002 | 성능 | 아이 등록·프로필 적용·처리 결과 저장의 성공 여부를 신속하게 반환해야 한다. | 기본 부하에서 요청 수신→저장 확정 응답 p95 ≤ 2초, 정상 요청 실패율 ≤ 1%. 실제 로봇 이동 시간은 제외하고 별도 기록한다. 저장되지 않은 요청의 성공 응답은 0건. |
| NFR-003 | 성능·기기 제어 | 드니가 위험물체를 인식한 후 3초 이내 위험 판단과 운행 정지를 완료해야 한다. | 첨부 NFR-DE-001 / 알파테스트. 기기 인식 시각→판단 및 실제 정지가 모두 완료된 시각 ≤ 3초. 정지 명령 접수로 대체하지 않는다. 기기·서버 시간 기준을 맞추고 지연·정지 실패를 함께 기록한다. |
| NFR-004 | 성능·알림 | 위험 판단 완료 후 5초 이내 보호자 푸시 알림 발송을 완료해야 한다. | 첨부 NFR-DV-001 / 알파테스트. 판단 완료 시각→확정한 발송 완료 시각 ≤ 5초. 공급자 접수인지 단말 수신인지 종료점을 확정해야 하며, 서로 다른 측정값을 혼용하지 않는다. |
| NFR-005 | 성능·용량 | 목표 동시 사용 부하에서 기능 저하 여부를 확인해야 한다. | 정의한 기본 부하를 30분 유지하며 NFR-001~003과 실패율 ≤ 1% 충족. 2배 부하(40세션·초당 10건)는 탐색 시험으로 실행하고 지연·실패율을 보고한다. 탐색 결과를 보장 용량으로 표현하지 않는다. |

## 6. 안정성·데이터 무결성

| NFR-018 | 정확성·일관성 | 같은 객체·프로필·위험 기준에는 재현 가능한 판단 결과를 제공해야 한다. | 승인된 객체×성장단계 규칙표의 정의된 조합 100%를 정답 사례로 시험하고 위험도·사유 일치율 100%. 기준 없는 조합을 임의 정상 등급으로 분류한 사례 0건. 이는 규칙 구현 정확도이며 카메라 감지 성능과 구분한다. |
| NFR-019 | 정확성·자동 전환 | 지원 월령 경계 도달 시 성장단계가 확정된 기준대로 자동 전환되고, 지원 범위 밖으로 넘어가면 임의의 프로필을 적용하지 않아야 한다. | 첨부 NFR-TS-001 / 클로즈 베타테스트. 12·24·36·96개월 직전·도달·직후에서 기대 단계 또는 지원 범위 밖 상태·프로필·변경 이력 일치율 100% 확인. 월령 계산의 시간대·월말·윤년 규칙 확정 후 시험한다. 판정 함수 시험만으로 자동 실행 검증을 대신하지 않는다. |

## 10. 검증 산출물과 확정 순서

각 시험 결과에는 **NFR ID, 빌드·환경, 시험 일시, 입력 조건, 표본 수, 실제값, 목표값, 판정, 증거 위치, 미해결 사유**를 기록한다. 정상 사례만 측정하거나 실패·시간 초과를 지연 표본에서 제거한 뒤 성공으로 보고하지 않는다. 지연 분포는 완료 표본 기준임을 명시하고 실패율을 반드시 함께 제시한다.

1. 기능 명세의 D-01~09 및 실제 단말·기기·외부 연동을 확정한다.
2. 본 문서의 부하·성능·복구·삭제 목표를 검토하고 적용 기준을 고정한다.
3. 규칙·접근 제어·중복·실패 주입·접근성 시험을 수행한다.
4. 실제 기기와 선택한 푸시 채널의 성능을 별도로 측정한다.
5. 정책 미확정·미검증 항목은 통과와 구분하여 남긴다.

**기능 요구사항은 무엇을 구현할지, 비기능 요구사항은 그 기능이 어느 품질 수준으로 동작해야 하는지를 관리한다.** 숫자로 확인 가능한 항목은 제안 목표를 제시했으며, 위험 기준·연령 정책·감지 성능처럼 원문에 근거가 없는 제품 정책은 임의로 확정하지 않았다.
