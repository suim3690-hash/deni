# 하드웨어 지원 기능

> 하드웨어 담당자가 실제 코드와 장치 동작을 기준으로 작성하는 통합 범위 표

상태는 `지원`, `부분 지원`, `개발 예정`, `지원 불가`, `확인 필요` 중 하나를 사용한다. 확인되지 않은
기능을 프론트에서 활성화하거나 백엔드에서 성공으로 처리하지 않는다.

## 1. 명령 수신 기능

| 기능 | 상태 | 입력값 | 실제 완료를 판단하는 값 | 담당자 메모 |
| --- | --- | --- | --- | --- |
| 일시정지 `PAUSE` | 확인 필요 | `commandId` | `PAUSED` 상태 보고 | |
| 재개 `RESUME` | 확인 필요 | `commandId` | `RUNNING` 상태 보고 | |
| 완전 정지 `STOP` | 확인 필요 | `commandId` | 하드웨어 정의 필요 | `PAUSE`와 차이 확인 |
| 위험물 재검사 `RECHECK_HAZARD` | 확인 필요 | 위험 ID·이벤트 ID | 위험물 존재 여부 | |
| 안전 위치 이송 `RELOCATE` | 확인 필요 | 위험 ID·안전 위치 | 실제 이송 완료·실패 | |
| 위험 탐지 시 자동 정지 | 확인 필요 | 모델 탐지 결과 | 정지 상태와 원인 | |

## 2. 상태·센서 데이터

| 데이터 | 상태 | 값·단위 | 권장 주기 | 현재 백엔드 저장 위치 |
| --- | --- | --- | --- | --- |
| 동작 상태 | 입력 형식 준비 | `RUNNING`·`PAUSED`·`RELOCATING`·`UNKNOWN` | 변화 시 + 1초 | `robot_live_state` |
| 이동 상태 | 입력 형식 준비 | `FORWARD`·`TURNING`·`BACKWARD`·`STOPPED`·`UNKNOWN` | 변화 시 + 1초 | `robot_live_state` |
| 현재 구간 이동 시간 | 입력 형식 준비 | ms, 미측정은 `null` | 상태와 함께 | `robot_live_state` |
| 현재 구간 이동 거리 | 입력 형식 준비 | m, 미측정은 `null` | 상태와 함께 | `robot_live_state` |
| 배터리 | 확인 필요 | 0~100% | 변화 시 또는 상태와 함께 | `devices` 확장 검토 |
| 로봇 위치·방향·속도 | 확인 필요 | 좌표계·단위 미정 | 하드웨어 확인 후 결정 | 미정 |

`입력 형식 준비`는 DB와 조회 API가 있다는 의미이며 실제 하드웨어가 값을 제공한다는 의미는 아니다.

## 3. 모델 탐지 데이터

| 데이터 | 상태 | 현재 계약 |
| --- | --- | --- |
| 이벤트 ID | 입력 형식 준비 | 중복되지 않는 UUID, 재전송은 같은 ID |
| 모델 종류 | 입력 형식 준비 | `HAZARD` 또는 `OBJECT` |
| 물체 라벨 | 입력 형식 준비 | 공백이 아닌 최대 100자 |
| 감지 시각 | 부분 지원 | 현재 DB 최초 수신 시각. 실제 촬영 시각은 추가 필요 |
| 바운딩 박스 이미지 | 입력 형식 준비 | JPEG/PNG, 최대 5MiB |
| 위험도·판단 사유 | 확인 필요 | 모델 출력인지 백엔드 규칙인지 결정 필요 |
| 위치·맵 좌표 | 확인 필요 | 좌표 제공 가능 여부와 좌표계 확인 필요 |
