# ThinQ Kids SafeGuard | PRD · MVP

> BX·CX 분석을 DX 구현으로 연결하기 위한 제품 요구사항 및 최소 구현 범위  
> 작성 기준: 2026-09-16 | 개정: v0.4 · 사용자 추가 첨부 기준 반영

## 문서 안내

이 문서는 **기획서에서 정의한 고객 문제와 서비스 가치**를 정리하고, **Front 유스케이스에 명시된 기능을 개발 범위와 완료 조건으로 연결**한다. PRD는 제품의 목적과 요구사항, MVP는 이번에 구현할 최소 기능 묶음을 다룬다.

| 근거 자료 | 확인 범위 | 문서 내 표기 |
| --- | --- | --- |
| [0916 BX_CX.pdf](0916%20BX_CX.pdf) | 전체 36페이지의 추진 배경, 조사·분석, 페르소나, 핵심 경험 및 솔루션 | PDF p.번호 |
| [유스케이스 명세서 Front.py](유스케이스%20명세서%20Front.py) | TKS_001~TKS_007 전체 | 해당 TKS 번호 |

PDF 페이지 번호는 파일에서의 페이지 순서다. Front 파일은 확장자가 `.py`지만 내용은 유스케이스 표로 작성된 명세서다.

**작성 원칙**

- 두 원문과 이후 사용자가 확정한 변경 내용을 사용한다. 외부 자료, 임의의 정책, 기술 스택, 일정, 인력, 목표 수치를 추가하지 않는다.
- 원문에 없는 세부사항은 **‘원문 미정’**, 서로 맞지 않는 내용은 **‘원문 확인 필요’**로 남긴다.
- MVP 범위는 **기존 TKS_001~007과 추가 합의한 TKS_008 월간 성장 리포트 조회의 총 8개 유스케이스**다. 기존 7개는 우선순위 ‘상’, 리포트는 ‘중’이다.
- 원문의 목표·기대 경험과 실제 달성 결과를 구분한다. 구현 가능성이나 성과가 검증되었다고 표현하지 않는다.
- 기존의 별도 PRD·MVP 파일을 이 문서로 통합한다. 원본 PDF와 Front 명세서는 변경하지 않는다.

추가 첨부를 최신 작성 기준으로 적용한다. TKS_008은 성장단계 변화·위험물 감지 통계·안전조치 변경사항·다음 단계 안전 기준 예고를 포함한다. TKS_005에는 위험물 판단 시 드니 운행 즉시 정지를 추가한다. 이전에 축소했던 리포트 범위는 이번 사용자 지시로 대체한다. 내용상 충돌만 [첨부 기준 정리](첨부내용_반영점검.md)에 남긴다.

### 1.3 고객 유형과 최종 페르소나

기획서는 다음 세 가지 Actor를 제시한다. [PDF p.23~25]

| Actor | 유형 | 주요 관심 |
| --- | --- | --- |
| Actor 1 | 발달 및 안전을 챙기는 올케어 부모 | 아이 발달과 안전, 잘 돌보고 있다는 확신 |
| Actor 2 | 육아·가사 부담형 부모 | 반복되는 육아·살림 부담 완화, 시간과 여유 확보 |
| Actor 3 | 가전 가사자동화 적극 활용자 | 가전 비교·활용, 자동화, 아이가 있는 환경에서의 안전한 사용 |

**최종 페르소나: 손지아, 31세**  
육아와 집안일 부담을 배우자와 로봇청소기에 나눠 맡으려는 부모다. [PDF p.31]

- **상황:** 시간대별로 육아를 나누기로 했지만 실제 부담은 한쪽에 쏠린다. 아이가 기어다니거나 신생아가 생기는 생활 변화로 직접 청소할 여력이 줄어든다.
- **바람:** 청소만이라도 로봇청소기에 맡겨 부담을 덜고 싶다.
- **목표:** 육아를 실제로 공평하게 나누고, 생활이 바뀌어도 로봇청소기가 안전하게 집안을 관리해주길 바란다.

### 1.4 페인 포인트와 원문의 대응 방향

| 페인 포인트 | 기획서의 경험 확대 방향 | Front에서 구체화된 관련 기능 |
| --- | --- | --- |
| 공동육아를 해도 실제 부담이 한쪽에 쏠림 | 확인·기여도 기록보다 로봇이 일을 맡아 전체 노동량을 줄임 | 안전 위치로 이동, 처리 후 청소 재개 가능 상태 |
| 새벽 수유·잠투정으로 수면이 끊기고 피로가 이어짐 | 아이 수면 시간을 피해 청소 시점 조정 | 해당 기능의 상세 유스케이스 없음 |
| 아이의 생활 변화로 직접 청소할 여력이 부족함 | 위험 요소를 미리 치우는 자동화 | 위험물체 감지, 위험 판단, 안전 처리 |

| 청소 전 정리와 청소 중 아이 안전을 반복 확인해야 함 | 아이와 함께 생활하는 공간의 청소를 안심하고 맡기는 경험 | 위치·사진·위험 사유 확인, 알림, 안전 처리 |

근거: PDF p.11·31~33, TKS_003~007. 기능 간 관련성을 정리한 표이며, 모든 고객 문제가 현재 Front 기능만으로 해결되었다는 의미는 아니다.

## 2. PRD: 제품 요구사항

### 2.1 제품 정의

**ThinQ Kids SafeGuard**  
기획서의 솔루션 문구는 **“위험은 감지하고, 육아는 가볍게 만드는”**이다. [PDF p.32·36]

Front 명세서에서 구체화된 서비스는 드니가 바닥의 물체를 인식하고, 아이의 성장단계 Safety Profile에 따라 위험도를 판단해 보호자에게 알리며, 보호자가 위험 상세를 확인한 뒤 직접 제거 또는 안전 위치 이동으로 처리하는 흐름이다. [TKS_001~007]

월간 성장 리포트는 선택한 월의 성장단계 변화, 위험물 감지 통계, 안전조치 변경사항을 제공하고 다음 성장단계의 안전 기준을 예고한다. 위험물로 판단하면 드니의 운행을 즉시 중단하고 위험 알림을 발송한다. [추가 첨부 TKS_005·008 및 FR-AD-400]

### 2.2 BX·CX·DX 목표

| 관점 | 목표 | 근거 |
| --- | --- | --- |
| BX: 사업 관점 | 영유아 양육 가정을 주요 타깃으로 LG 로봇청소기의 구매 선택률을 높임. 가전·ThinQ·케어 강점을 육아 가정의 문제 해결과 연결 | PDF p.6·8 |
| CX: 고객 관점 | 보호자가 청소 전 바닥을 일일이 정리하거나 청소 중 아이 안전을 반복 확인하지 않아도, 생활 공간의 청소를 안심하고 맡기는 경험 | PDF p.11 |
| DX: 구현 관점 | 아이 정보와 기기 상태를 바탕으로 감지·판단·알림·상세 확인·안전 처리와 월간 성장 리포트를 서비스 기능으로 연결 | TKS_001~008 |

구매 선택률 향상이나 부담 감소의 정량 목표는 원문에 없다. 이 문서는 임의의 목표값을 설정하지 않는다.

## 3. MVP: 이번 최소 구현 범위

### 3.1 선정 기준

**MVP는 TKS_001~TKS_007의 ‘성장단계 기반 위험 감지·알림·안전 처리’와 TKS_008의 ‘월간 성장 리포트 조회’로 구성한다. 총 8개이며 리포트는 우선순위 ‘중’이다.**

선정 이유는 다음과 같다.

1. 기획서의 사진·위치 기록, 발달단계별 판단, 위험 감지·알림 경험을 Front 초안이 구체적인 동작으로 정의하고 있다. [PDF p.33, TKS_003~006]
2. Front 초안은 7개 기능 모두의 우선순위를 ‘상’으로 지정한다. [TKS_001~007]
3. 안전 처리는 직접 제거와 안전 위치 이동 두 경로를 명시한다. MVP에서도 두 경로와 대안 흐름을 유지한다. [TKS_007]
4. 월간 리포트는 첨부에 명시된 성장단계 변화·감지 통계·안전조치 변경사항·다음 단계 예고를 포함한다. [TKS_008]

이는 **문서에 정의된 최소 서비스 범위의 선정**이며, 기술 구현 가능성·일정·성능을 확정하는 판정이 아니다.

### 3.2 MVP 기능 목록

| 순번 | MVP 기능 | 구현할 내용 | 근거 |
| --- | --- | --- | --- |
| 1 | 기기 연결 상태 확인 | 온라인/오프라인 표시, 오프라인 안내·실시간 기능 제한 | TKS_001 |
| 2 | 아이 정보 등록 | 이름·생년월일 입력, 빈 값·미래 날짜 검증, 저장 | TKS_002 |
| 3 | 성장단계 적용 | 월령 계산, 단계 판정, Safety Profile 연결·저장, 요약 표시 | TKS_003 |
| 4 | 위험물체 감지 | 드니 객체 인식 데이터 수신, 객체·위치·시간 저장 | TKS_004 |
| 5 | 위험도 판단·정지·알림 | 프로필 기반 판단, 위험물 판단 시 즉시 정지 및 푸시, 결과 저장 | TKS_005 |
| 6 | 위험 상세 확인 | 홈에서 맵 진입, 상세 정보 표시, 처리 방법 선택 | TKS_006 |
| 7 | 안전 처리 | 직접 제거 또는 지정 안전 위치 이동, 결과 저장, 청소 재개 가능 상태 | TKS_007 |
| 8 | 월간 성장 리포트 조회 | 이번 달 기본 조회·월 변경, 성장단계 변화·감지 통계·안전조치 변경·다음 단계 예고, 빈 상태·실패 구분 | TKS_008 · 우선순위 중 |

### 3.3 MVP 전체 흐름

**사전 정보**  
아이 이름·생년월일 등록 → 개월수 계산 → 성장단계 Safety Profile 연결·저장 → 적용 결과 확인

**감지부터 처리까지**  
등록된 드니 연결 상태 확인 → 온라인 드니의 물체 감지 → 감지 데이터 저장 → Safety Profile과 비교 → 위험도 판단·저장 → 위험물 판단 시 운행 즉시 중단 및 푸시 → 홈 위험 알림의 위치 확인 → 맵·위험 상세 → 처리 방법 선택

**처리 경로 A: 사용자 직접 제거**  
제거 안내 → 보호자의 제거 완료 확인 → `처리 완료` 저장 → 청소 재개 가능 상태

**처리 경로 B: 안전 위치로 이동**  
드니가 지정 안전 위치로 이동 → 이동 완료 → `임시 안전조치 완료` 저장 → 청소 재개 가능 상태

**원문 대안 흐름**  
기기 오프라인·배터리 부족·이동 실패 → 이동 기능 사용 불가 안내 → 사용자 직접 제거 요청

위 흐름은 각 유스케이스의 기능 설명을 연결한 것이다. 원문 내 잘못 연결된 ID는 아래 확인 사항에서 별도로 다룬다.

**월간 리포트 조회**  
홈에서 리포트 진입 → 프로필·조회 권한 확인 → 이번 달 성장단계·감지·안전조치 변경 이력 집계 → 리포트 및 다음 단계 안전 기준 예고 표시. 월 변경 시 선택 월로 재조회한다. 기록이 없으면 0건·빈 상태를, 조회 실패이면 오류·재시도를 제공한다. 기기의 현재 온라인 상태는 과거 저장 이력 조회의 필수 조건이 아니다.

### 3.4 MVP 완료 확인 항목

아래 항목은 새롭게 만든 성능 목표가 아니라 **원문의 이벤트 흐름과 종료 조건을 확인 항목으로 정리한 것**이다.

| 확인 항목 | 원문 기준 기대 결과 |
| --- | --- |
| 홈에서 연결 상태 확인 | 정상 통신이면 온라인, 통신 불가이면 오프라인 표시 |
| 오프라인 안내 | `기기 연결을 확인해주세요` 표시, Safety Care 실시간 기능 제한 |
| 아이 정보 입력 | 빈 값·미래 날짜 여부 검증 후 유효한 정보를 저장 |
| 성장단계 적용 | 월령에 따른 프로필이 연결·저장되고 단계·기준 요약 확인 가능 |
| 감지 데이터 수신 | 객체 종류·위치 좌표·감지 시간이 저장되고 위험 판단으로 전달 |
| 위험도 산정 | 객체와 현재 프로필을 비교해 위험도를 산정하고 결과 저장 |
| 위험 대응 정지·알림 | 위험물 판단 시 실제 운행 정지와 위치·객체 요약 푸시. 정지·발송 실패는 별도 구분 |
| 위험 상세 | 위험도·객체명·위치·감지시간·AI 감지 이미지·위험 사유 표시 |
| 직접 제거 | 보호자의 완료 확인 후 `처리 완료` 저장 |
| 안전 위치 이동 | 이동 완료 후 `임시 안전조치 완료` 저장 |
| 이동 불가 | 오프라인·배터리 부족·이동 실패 시 사용 불가 안내와 직접 제거 요청 |
| 처리 이후 | 처리 상태 갱신, 청소 재개 가능한 상태 |
| 리포트 기본 조회 | 이번 달 성장단계 변화·감지 통계·안전조치 변경사항 및 다음 단계 예고 표시 |
| 리포트 월 변경 | 선택한 연도·월의 기록을 재집계하여 표시 |
| 리포트 데이터 없음 | 정상 조회 시 기록이 없으면 0건·빈 상태 표시로 조회 완료 |
| 리포트 접근·조회 오류 | 비인가 접근 제한, 조회·집계 실패 안내와 재시도, 실패를 0건으로 표시하지 않음 |
| 리포트 집계 일관성 | 동일 감지 기록의 중복 전송 제외, 당시 저장된 판단 결과 사용 |

연령 구간과 판단 기준처럼 원문이 확정하지 않은 사항은 기대값을 임의로 만들지 않으며, 해당 내용 확인 후 완료 여부를 판단해야 한다.
