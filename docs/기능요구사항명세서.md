# ThinQ Kids SafeGuard 기능 요구사항 명세서

> v0.3 | 2026-09-17 | 기준: 사용자 추가 첨부 8개 유스케이스 및 후속 사용자 결정

## 1. 범위와 표기

근거 문서: [PRD·MVP](PRD_MVP_ThinQ_Kids_SafeGuard.md), [유스케이스 다이어그램](유스케이스다이어그램.md), [유스케이스 명세서](유스케이스명세서.md), [Front 원문](유스케이스%20명세서%20Front.py).

MVP의 **8개 유스케이스를 구현 단위의 40개 기능 요구사항으로 구체화**한다. 요구사항 개수가 늘어난 것은 기능을 분해했기 때문이며, MVP가 40개로 늘어난 의미는 아니다. 다이어그램의 6개 묶음과 달리 추적 기준은 TKS_001~008이다.

- **[원문 기반]**: 기존 기능·대안 흐름을 구현 문장으로 정리했다.
- **[검토 후보]**: 기존 명세의 추가 예외 흐름 또는 이번 품질 요구를 구현하기 위한 보완이다. 원문 확정 사항과 구분한다.
- **[조건부]**: 해당 외부 API를 실제 사용하는 경우에만 적용한다. 특정 공급자·프로토콜은 지정하지 않는다.
- **우선순위 상**: 핵심 흐름 또는 잘못된 권한·완료 처리를 방지하는 항목. 원문의 핵심 기능은 모두 ‘상’이다. **중**: 핵심 흐름을 보조하는 복구·표현 항목. 후보의 우선순위는 본 명세의 검토안이다. ‘하’ 항목을 임의로 추가하지 않는다.
- ‘아이 정보 등록’, ‘프로필 적용 결과’, ‘안전 처리’는 기능이 제공되는 **화면 영역 명칭**이며 신규 독립 페이지 구성을 확정하지 않는다. 백그라운드 기능은 ‘화면 없음’으로 표기한다.
- FR-001~040은 기존 문서와 연결하기 위한 내부 관리 ID다. 첨부의 FR-AD·FR-UU는 출처 ID로 추적표에 연결한다. 첨부에 우선순위가 있는 항목은 해당 값을 우선한다.
